# Security: rules, controls, tests

Every rule below is enforced in code and, where marked, proven by a test in `backend/tests/`. Run them with `python -m pytest -q`.

## Non-negotiable rules

| Rule | How it is enforced | Test |
|---|---|---|
| No agent can send an email, book a meeting, or change a candidate's status | Agents only call `create_proposal`. The Action Gateway (`gateway/executor.py`) is the only code that changes state, and it runs a proposal only if it is `approved`, was approved by a recruiter or HR admin, and its payload hash still matches. Email and meeting executors do not exist yet (M2/M3) and will be added only to the gateway. | `test_gateway_refuses_a_pending_proposal`, `test_rejected_proposal_can_never_execute`, `test_approval_cannot_be_replayed`, `test_gateway_refuses_a_payload_changed_after_approval`, `test_screening_workflow_end_to_end` (all candidates stay `screened` until approval) |
| Every sensitive action needs explicit human approval | Approve and reject endpoints require an HR role, a session cookie and a matching CSRF header. | `test_employee_cannot_see_or_approve_proposals`, `test_missing_csrf_token_blocks_approval`, `test_unauthenticated_and_wrong_role_are_refused` |
| The system never accepts or rejects candidates on its own | Screening sets only processing states (`received`, `screened`, `screening_failed`). The only decision state, `shortlisted`, is written by the gateway after approval. There is no "rejected" status. | `test_screening_workflow_end_to_end` |
| Never trust instructions inside CVs or emails | Security Guard: hidden text (white, tiny, transparent, off-page, DOCX hidden runs) is removed before analysis and flagged; Unicode is normalised and invisible/bidi characters stripped; EN/FR injection rules run on hidden and visible text; CV text is wrapped in `<untrusted_document>` and cannot close the wrapper; high-risk CVs are never proposed automatically. | `test_hidden_text_is_removed_and_flagged_high`, `test_visible_injection_is_flagged`, `test_injection_rules_detect_attacks`, `test_injection_rules_do_not_flag_normal_cv_lines`, `test_sanitize_removes_invisible_and_bidi_characters`, `test_cv_cannot_close_the_untrusted_wrapper`, `test_screening_workflow_end_to_end` (attack CV scores the same as its clean twin; hidden claims ignored) |
| Ranking uses job-related criteria only | The scored profile has no identity fields; identity keys returned by a model are dropped and reported. Contact email is stored on the candidate, outside the profile. | `test_identity_does_not_change_the_score` (fairness twins), `test_identity_fields_from_the_model_are_dropped_and_reported`, `test_contact_email_is_kept_outside_the_scored_profile` |
| Scores are computed in deterministic code | `scoring.py`: met = 1, partial = 0.5, missing = 0, weighted by criterion. Years-of-experience criteria are decided in code, not by the model. Fixed tie-breakers. | `test_score_is_weighted_and_deterministic`, `test_ranking_tie_breakers`, `test_met_without_verified_quote_is_downgraded_and_years_decided_in_code` |
| Every evidence quote is verified against the original CV text | `evidence.py` keeps a claim only if its quote appears verbatim in the visible, sanitised text. Quotes that contain injection patterns are not evidence. "Met" without a verified quote is downgraded. | `test_profile_items_without_verbatim_quote_are_dropped`, `test_quote_containing_an_instruction_is_not_evidence`, `test_quote_matching_ignores_case_spacing_and_typography` |
| No cross-candidate exposure | Each CV runs through its own graph invocation with only its own text; criteria assessment sees only the blind profile. The gateway refuses candidates from another job. | `test_each_llm_call_sees_exactly_one_cv`, `test_gateway_refuses_candidates_from_another_job` |
| Structured LLM output is validated with Pydantic | `LLMClient.complete_json`: JSON mode, temperature 0, Pydantic validation, one retry with the validation error, then failure (the CV is marked `screening_failed`, never silently scored). | `test_valid_json_is_parsed_and_validated`, `test_invalid_output_is_retried_once_with_the_error`, `test_persistently_invalid_output_raises`, `test_requests_use_temperature_zero_and_json_mode` |
| Secrets stay out of source code | All configuration comes from environment variables (`backend/.env.example`). `.env` is git-ignored. Demo passwords are generated at seed time unless passed in the shell. | (review) |
| No real personal data in the demo | `data/samples/` is generated by `scripts/make_sample_cvs.py`; all names, emails and employers are fictional (`example.test`). | (review) |

## Other controls

| Area | Control | Test |
|---|---|---|
| Uploads | Extension and magic bytes must agree; size, page count, encryption, PDF JavaScript/launch actions, DOCX macros and embedded objects, zip-bomb ratio are checked; files are stored under random names with mode 0600; display names cannot traverse paths; duplicates are refused. | `test_rejects_bad_files`, `test_rejects_too_many_pages`, `test_rejects_too_large`, `test_rejects_docx_with_macros`, `test_display_name_cannot_traverse_paths`, `test_upload_rejects_bad_and_duplicate_files` |
| Sessions | argon2id hashes; 30-minute JWT in an httpOnly, SameSite=Strict cookie; double-submit CSRF token; uniform login errors; 5 attempts per minute per IP; lockout for 15 minutes after 10 failures. | `test_session_cookie_is_httponly_and_samesite_strict`, `test_wrong_password_and_unknown_user_get_the_same_answer`, `test_login_rate_limit`, `test_account_locks_after_repeated_failures`, `test_tampered_session_token_is_refused` |
| Audit | Append-only: PostgreSQL triggers block UPDATE, DELETE and TRUNCATE on `audit_log`. Hash-chained: each entry hashes the previous one, so edits made with the triggers disabled are still detected. | `test_audit_log_is_append_only_in_the_database`, `test_hash_chain_detects_tampering_even_if_triggers_are_bypassed` |
| HTTP | `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, restrictive CSP on API responses, `Cache-Control: no-store`. The React app renders all CV-derived content as text, never as HTML. | `test_session_cookie_is_httponly_and_samesite_strict` |

## Known limitations

- Text hidden *behind* an image or shape is not detected; only colour, size, transparency and position are checked.
- The login rate limiter is in memory, per process. With several API workers, use a shared store.
- Prompt Guard (`PROMPT_GUARD_MODE=groq|local`) is implemented and fails loudly with a `classifier_error` flag, but it has not been run against the live model yet.
- The schema is created with `create_all`; there are no migrations yet.
- In production, the application's database user must not own `audit_log` (an owner can drop the triggers). Create the table and triggers with a separate admin role and grant the app user `INSERT, SELECT` only.
- `COOKIE_SECURE` must be `true` when served over HTTPS.
